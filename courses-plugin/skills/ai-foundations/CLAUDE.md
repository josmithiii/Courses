# ai-foundations -- project context

This is the `ai-foundations` course inside the public **Courses** repo
(`..`). A self-paced daily AI tutoring system: go from the MLP up to
modern LLMs, CNNs, Transformers, and Diffusion, using Python/PyTorch,
~1 hour/day, intuition-first. Adapt to the learner profile recorded in
their `progress.md` -- don't assume their level.

## Content vs. learner state (architecture)
Shipped course **content** is this skill's folder and is read-only at runtime.
Personal **learner state** (`progress.md` and `lessons/YYYY-MM-DD.md`) lives in the
learner's data root, resolved as described in `SKILL.md` under "Content vs.
learner state". Never write personal progress into this folder.

## Reminders
Two ~11:00 daily reminders (a local macOS launchd dialog + a remote Slack DM) only
*nudge* the learner to run `/lesson`; they do not read or pre-draft anything.

## Working with the learner
Be patient, friendly, analogy-first. One concept at a time. Always verify a concept
with a small exercise before advancing. Never rush past something unverified.
Keep sessions ~1 hour. Always update the data-dir `progress.md` and the day's
lesson file at the end.

## Diagrams
`the-diagram-atlas.md` holds the famous picture for each architecture buzzword, by
topic. Reading these is a course outcome: a learner should be able to name any of
them, say which of the five grammars it uses, and trace an input through it. The most
useful single idea is that a line in an MLP is one weight, while an arrow in a
Transformer is a whole tensor. When a new architecture joins the syllabus, add its
entry and check any figure number against the paper itself.

`visual-tour.md` is generated from the syllabus and the atlas: every topic in order,
with each entry annotated by its image search and exact figure page. Don't edit it.
After changing either source, run `tools/build_visual_tour.py`, adding any new external
figure to the tables in that script.

`figures/*.svg` are our own diagrams, generated by `tools/build_figures.py` in one
visual language: teal is data, orange has trained weights, gray is a fixed operation,
purple is model output. Each atlas entry names its file in a **Figure** field. Compute a
figure from its formula where that's possible, label anything schematic as illustrative,
and check every drawn figure against the paper's, by eye: the build can't see overlaps.
They teach alongside the famous originals
rather than replacing them, since those are what learners will meet elsewhere. No text
goes below size 21; the build fails if it does, or if text leaves its canvas or box.
Learners can open `figures/gallery.html` in a browser to see them all with a size slider.
